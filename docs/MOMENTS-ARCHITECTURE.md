# Moments 接入与分享架构

本文记录 BrainCore v4.0.0 中仍然有效的 Moments 设计决策。历史修复应优先转化为这里的契约或自动化测试，不再长期堆叠在生产代码里。

## 数据边界

- Moments 正文只写入 `读&写/Moments/YYYY.md`，并按月、周、日组织。
- 图片写入 `Boxes/图片`，其他附件写入设置中的 Boxes 附件目录；分享头像同样位于 `Boxes/图片`。
- 删除正文会直接从年文件移除，不再写入 `_trash.md`。刚删完界面上有短暂撤销。附件只有在整个库的 Markdown 与分享头像都不再引用时才可视为孤立。
- Moments 的**设置**（含分享水印等）存在插件 `data.json` 的 `momentsSettings` 字段里，不写进年文件。

## Mac App 写入规范

Mac 菜单栏 App 与插件写的是同一批文件。外部程序（Mac App、脚本、Shortcuts）向年文件追加内容时，必须严格遵守下面的格式，否则插件解析器会定位不到条目，编辑与删除有丢数据风险。

### 年文件结构

真实来源：`src/moments-memoria/store.ts` 的 `insertMemoIntoYear` / `periodHeadings`，以及 `src/moments-memoria/parser.ts` 的 `renderMemo`。

```text
读&写/Moments/2026.md

# 08月                     ← 月标题，H1，两位数月份 + “月”
## 第35周                  ← ISO 周标题，H2，“第N周”
### 2026-08-25 周二        ← 日标题，H3，YYYY-MM-DD + 空格 + 周X
- 09:30                    ← 时间行，H:mm 两位补零，独占一行
  今天的第一条记录。        ← 正文，每行缩进 2 个空格
  第二行同样缩进 2 空格。

---                        ← 每条记录以分隔线收口
```

要点：

- 年份由**文件名**承载，文件里**不写** `# 2026`。
- 月 / 周 / 日三级标题只在该分组第一次出现时写入，已存在就直接往下追加。
- 同一天内的条目按时间升序排列。
- 时间行是 `- HH:mm`，后面不跟正文；正文另起一行并缩进 2 个空格（空行保持真正的空行，不要缩进）。
- 每条记录后面跟一个空行 + `---`。

### 正例

```markdown
### 2026-08-25 周二

- 21:14
  和 J 聊了一小时，关于要不要把周报自动化。
  结论：先手写两周，攒够样本再说。

---
```

### 禁止项

- ❌ 紧凑单行 `- 21:14 内容`（老格式，解析器还能读，但新写入一律不要用；内容以 `{`、`>`、`- [ ]` 开头时会破坏渲染）。
- ❌ 正文不缩进，或缩进用 Tab / 4 空格。
- ❌ 省略 `---` 分隔线，或用 `***`、`___` 等等价写法。
- ❌ 自己写 `# 2026` 年份标题。
- ❌ 时间不补零（`- 9:30`）、用 12 小时制、或带秒。
- ❌ 把同一天的条目插到已有更晚时间的条目后面（破坏升序）。
- ❌ 直接改写整份年文件：并发写入时会覆盖插件刚写的内容。请只做定位追加。
- ❌ 往年文件里写 Moments 的配置或打卡数据。

### 双通道：正文走年文件，习惯数据走 data.json

| 数据 | 通道 | 写法 |
|------|------|------|
| Moments 正文 | `读&写/Moments/YYYY.md` | 按上面的格式追加 |
| Moments 设置 | `.obsidian/plugins/braincore-lifeos/data.json` → `momentsSettings` | 读改写整个 JSON |
| 习惯打卡 | 同一个 `data.json` → `habitData` / `habitsConfig` | 读改写整个 JSON |

插件会 stat `data.json` 的 mtime（桌面约 2 秒、移动端约 8 秒一次），发现外部改动后只合并 `habitData`、`habitsConfig`、路径等关键字段并局部刷新打卡区，不会整页重绘。外部程序写 `data.json` 时必须先读后写、保留未知字段，不要整表替换。

## Dashboard DOM 契约

- Dashboard 不拼接业务数据 HTML，不使用内联事件，也不暴露按钮级全局函数。
- 文本全部通过 `textContent` / `setText` 写入；图标 SVG 只来自源码常量，并通过受控解析插入。
- 交互集中在模块容器的事件委托中；对外只暴露版本化的 `BrainCoreAPI`。
- 天气和金句缓存保存结构化数据，不缓存可执行或可回灌的 HTML。

## 分享生成契约

- 单条与多条分享共用八种主题和一个底部水印；多条分享只出现一次水印。
- 多条分享最多 12 条，估算高度预算为 12000 px。选择器实时显示数量与高度预算，超额选择会被拒绝。
- 排版、图片加载与导出按记录推进进度；所有耗时生成均可取消。
- 复制失败不会自动下载，必须由用户明确选择“重试复制”“改为保存”或“取消”。
- 多条分享的日期时间左对齐、无边框；每条正文独立纵向排列，不套用单条分享的自适应双栏算法。
- 所有主题共用同一条正文左轴：内容槽宽 680 px，900 px 画布下起点为 110 px。短文只做垂直居中，文字块不再水平居中；多条分享的日期与正文也必须对齐这条左轴。
- 分享画布和底部水印宽度由同一个 900 px 根节点决定，水印不得产生额外左右边距。

## 八主题视觉契约

- 主题名称固定：纸张白、牛皮纸、薄荷绿、蜜桃粉、晴空蓝、薰衣草、午夜蓝、木炭黑。
- 纸张白使用纯黑水印；其余七种使用纯白水印，不使用磨砂或渐变水印。
- 纸张白为简洁纸张、牛皮纸为手写纸张、薄荷绿为和风纸张、木炭黑为暗色纸张。
- 视觉回归覆盖：亮色宿主、暗色宿主、纯文字、图文和窄屏预览。浏览器原生输出的 JPEG 基线保存在 `tests/visual/baselines/`。

## 历史修复迁移原则

- 解释“为什么”的注释保留并尽量指向本文件；描述某次临时补丁或版本号的注释应迁移为测试。
- 删除代码前先证明无入口、无导出、无样式选择器引用；阅读、画册和七套作品导出的撤除由发布检查持续守护。
- 不做无差别清理：LifeOS 公共模块、旧版本更新日志和外置使用说明属于家族化共享机制，应保留单一真实来源。
